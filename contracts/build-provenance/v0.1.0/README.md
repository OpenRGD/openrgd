## Evidence and trust

Use [in-toto Statement v1](https://github.com/in-toto/attestation/blob/main/spec/v1/statement.md), [SLSA Provenance v1](https://slsa.dev/provenance/v1) and [DSSE](https://github.com/secure-systems-lab/dsse) (actual securesystemslib 1.6.0 Envelope). No custom cryptographic signature algorithm. This is an explicitly restricted application profile, NOT a general SLSA parser, a level claim or a production build service. Reject unrecognized fields rather than silently treating arbitrary attestations as this exact profile.

An independently provisioned builder policy binds module/release, repository identity, exact Git commit, SHA-256 source inventory, recipe bytes, package root, build type, builder ID and Ed25519 key material. The operator supplies the trusted local repository mapping and policy separately from the producer; no automatic trust of repository URL, remote configuration, self-declared builder, DNS or Git author. Exact policy digest is retained. The caller must authenticate and manage policy/keys outside this prototype; no expiry, key rotation or revocation service here. The Registry adapter also requires builder key material distinct from current TUF root/timestamp/snapshot/targets and selected publisher keys. Separation of keys is not organizational independence or production custody.

## Restricted source and build type

BuildType: `https://openrgd.org/build-types/pure-python-wheel-review/v0.1-candidate`. One tracked source tree rooted at pyproject.toml plus one import package. Git SHA-1 object format only for this candidate; exact commit object (not a ref, tag, branch or working-tree content). Local operator-provisioned trusted repository/object store, no remotes fetched, replacements disabled, no source scripts executed by verifier. Read regular 100644 blobs only; no links, submodules, executable mode, path aliases, extra tree roots or unbounded artifacts. 128 files, 64 KiB/file, 1 MiB total source bytes. Git subprocess time/output limits are review bounds in a trusted local repository, not a sandbox for hostile Git configs, objects or concurrent replacement. SHA-256 over sorted source path/raw hash/size list in existing local deterministic encoding is a **distinct** inventory commitment (not OpenRGD V1, Git tree OID, tarball or canonical signing JSON).

The builder fixture creates a real Git commit before building; builds from a fresh materialization of the verified exact blobs using the previously pinned test build tools, signs a Statement for the actual wheel. No importing/installing providers. Existing wheel verifier independently recomputes proposal/manifest/descriptor and RECORD commitments. Verify that all package paths and bytes in the actual wheel match the committed source package exactly; generated dist-info is assessed by existing wheel verifier. This narrow profile cannot establish general native compilation equivalence; no inference that arbitrary output comes from source just because it is signed.

Statement: _type https://in-toto.io/Statement/v1; predicateType https://slsa.dev/provenance/v1; exactly one subject (wheel filename + SHA-256). buildDefinition includes exact buildType, externalParameters repository/commit/packageRoot, empty internalParameters in this fixture profile, and exactly two resolvedDependencies: git+<repository>@<commit> with gitCommit and SHA-256 inventory; same URI #pyproject.toml with SHA-256 recipe. runDetails includes builder.id and invocationId. Dependencies here are the required source/recipe commitments only; **not** all build dependencies, environment, materials or independent execution proof. Build command is the test harness's fixed no-isolation wheel build. No timestamp or freshness claim from invocation ID. Verify DSSE payloadType application/vnd.in-toto+json and one Ed25519 signature using separately provisioned policy key; do not trust payload key or use a key ID as authority. Validate exact subject, build definition and source/recipe against actual objects and independent policy. No source URL used as network or filesystem locator.

The resulting ProvenanceReview records verified source membership, policy/signature and exact wheel source-package correspondence, with explicit negative flags for independent build execution, full materials, reproducibility, SLSA level and grants. This is a signed builder *claim with verified bindings*, not proof of a trustworthy build platform. Existing ReleaseProposal and WheelInspection retain their original negative flags. Do not cast the new evidence to a published release. Policy and evidence retained separately from the legacy model digest.
