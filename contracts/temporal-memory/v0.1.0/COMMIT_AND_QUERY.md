# D-HISTORY-01 — History write vs bitemporal Memory (candidate)

A Work-admitted goal is not History authorization. The model may propose a cognitive commitment, revised annotation, salience or Oneiric computation. Canonical history needs a separate `HISTORY_COMMIT_REQUEST` exact operation grant under independently verified Core-C Life binding/current writer role. The receiver, not the sender, resolves the lease/fencing generation, issuer custody, permission, context and payload hash.

The real History writer must provide an authenticated durable receipt and idempotent lookup. A lost ACK after successful append is an **ambiguous** requester outcome, not permission to generate a different key or another Chronon. `NOT_CONFIRMED` may have no committed Chronon/ledger watermark fields. The fake writer in tests models only these behaviors.

`AS_KNOWN_AT(T)` selects what was actually committed/available by T in a verified clock domain, never a backdated knowledge claim. `CURRENT_ASSESSMENT_OF(T_event)` uses newest derived annotation. `supersedes` must bind the same subject and preserve original evidence; privacy can redact/hide media even from historical views. No database, binary writer ABI, signature scheme or network query protocol is frozen here.
