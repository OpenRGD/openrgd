## Concrete gaps / disposition

**RI-A02/A04:** Keep the compact schema unchanged. Need one owner-reviewed bounded resolver for metadata and optional payload (separate permissions, principal/purpose/consent, expiry, revocation, availability, store scope, immutable envelope revision/commitment, original producer session/boot). No reference-as-token. Unknown, denied, withheld, unavailable, redacted and erased are not equivalent. Core-D EvidenceAvailability requires assessed time/domain, producer, reason and a concrete state; it lacks UNKNOWN. Without an actual assessment return no D record/unknown locally, not fabricated AVAILABLE or ERASED. Hash presence does not prove retained/accessible media. L0 may be discarded; RI legacy store is not a compliant L1 Vault; L2 remains History, L3/L4 derived.

**RI-A05:** verified_ref_from_store calls store-wide verify then get_observation. Review stable snapshot / point-in-time verification, bounded cost and verification scope (payload vs envelope); no guarantee across the check/read interval. Tests characterize the legacy distinction: a changed camera source metadata field before any derivation may still pass payload checks, whereas a changed generic envelope is rejected. This is not permission to edit an archive or a claim of production exploitation. Fix in RI-owned additive review, not Core. No expensive verify on sensor/real-time paths.

**RI-A06/A11:** existing Agent temporal profile §11 is subject to Core-D's proposed non-retroactive legacy import delta. Distinguish source event time, userspace receipt, actual import/commit and derived knowledge time. No backdated anchors. Cross-host uncertainty and Chronograf resolution remain open. A read-only notice is not a qualifying source sample, numeric IMU reading, or grant.

**RI-A08:** keep observation, derived interpretation, lifecycle/delivery report, and cognitive proposal disjoint. RI v0.4 DerivationStore already links immutable observation envelope bytes and forbids SELF labels. Feedback #6 driver delivery is not optical/acoustic evidence. Voice #9 and Visual #11 reports are not stored observations; preserve these types rather than wrap them as sensor samples. COG #8 remains metadata-only; Console/Pulse live paths unchanged; CAL #5 sidecar remains independent. EVOL #16 mutation/as-built claims are neither raw observation nor verified identity. No inference, capture, feedback renderer, hardware control or provider copied into Core.

## Minimal adapter — proposed boundary, not a second runtime

Core should own **this crosswalk and cross-repo conformance** only. Existing RI producer and owner-specific consumers remain in their repos. Do not introduce another ObservationRef or require hardware publishers to import any draft Core package.

Future, after RI-A02/A04/A05 and independent owner review:
1. Authorized History-side requester resolves existing RI ref against immutable original envelope and permitted bytes, binding scoped identity, exact content, source session/boot/frame and availability/provenance (no fetch from arbitrary strings). Metadata-only consumers need not read bytes. Fail/defer on mismatch, missing access, unknown/expired proof.
2. If selected for persistence by explicit policy, form a **typed observation/evidence-link payload** referencing the original scoped observation, immutable envelope commitment, exact content digest and classification; keep externally qualified time and independently verified binding/as-built/calibration refs as separate proofs. Preserve unknown sensor event time. This is a proposed future versioned payload profile, NOT an existing record or approved schema.
3. **Real gap:** Core-D HistoryCommitRequest.payload_kind currently allows LEGACY_IMPORT, MEMORY_ANNOTATION, COGNITIVE_COMMITMENT, ONEIRIC_REVIEW, EVIDENCE_AVAILABILITY only. It does NOT allow ordinary source observation, derived perception or producer lifecycle report. An ordinary RI record cannot be silently cast as LEGACY_IMPORT or MEMORY_ANNOTATION; legacy import requires genuine historical assertion and new import anchor. Do not overload payload_sha256 with raw media hash when the requested payload is the link record.
4. If owners agree, negotiate an additive/versioned History payload kind/profile (observation/evidence link first; derived/report semantics separately) and exact request/payload commitment. For a Life-scoped history, Core-C binding/activation/lease are verified externally; the writer verifies caller, current scoped writer fence, independent Core-B HISTORY_COMMIT_REQUEST effect gate for that exact request/target, policy, time and consent. Observed robot, consuming agent, requesting principal and writer may all differ.
5. Only the external writer appends and issues authenticated receipt + watermark + measured commit anchor; same-key idempotent retry/query handles lost ACK; conflicting request fails. NOT_CONFIRMED remains uncertain, no fake Chronon. One shared original evidence object does not require one history commit per robot or per raw sample.

**No History adapter implementation now:** real resolver, Chronograf, identity, permission and writer interfaces are not demonstrated here. A separate opt-in owner PR can implement the bridge after review. No new canonical schema, Core runtime, production resolver, writer, grant or pilot in CORE-RI-01.
