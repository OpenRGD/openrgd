```text
DEFAULT SEED: 76 expected, 0 missing, 0 mismatched,

```

`spec/` is the human-readable authority. `standard/` is its strict JSON leaf mirror. The packaged default seed is a derived runtime profile.

A future seed divergence requires an explicit `RUNTIME_PROFILE_OVERRIDE` with a semantic reason, decision reference and both canonical/seed SHA-256 values.

## Closure 2 — runtime and safety ownership

The historical bundled ROS 2/Viam runtime was incomplete and referenced a nonexistent `02_operation/safety_supervisor.jsonc`. It was preserved as historical evidence and removed from the installed package rather than repaired by guessing.

`rgd run` now exposes only a non-actuating status/migration boundary. Legacy runtime targets fail closed with exit code `2` and import no middleware, serial or CAN libraries.

Physical execution belongs to an independent embodied runtime and Body Adapter implementing:

```text
CognitionProposal
→ ActionIntent
→ Somatic Translator
→ CapabilityPlan
→ Operation Safety Gate
→ DecisionTrace
→ Body Adapter
→ hardware
```

## Closure 5 — USDA evidence and static profile inspection

### Text USDA evidence profile

The old USD parser embedded machine-local paths, interpreted angular limits with the wrong unit assumption and supplied convenience defaults.

The reconciled path accepts UTF-8 text USDA only and declares a narrow profile:

```text
OPENUSD_USDA_LIGHTWEIGHT_V1
```

It supports directly authored stage metadata plus `PhysicsRevoluteJoint` and `PhysicsPrismaticJoint` evidence. It records source filename, format, byte count and SHA-256.

Evidence-bound conversions:

```text
revolute position     degree → radian
prismatic position    stage distance × metersPerUnit → metre
drive effort          SI conversion only with authored
                      metersPerUnit + kilogramsPerUnit
```

Raw source values remain preserved. Missing values remain absent. Non-finite values, inverted limits, duplicate identifiers and ambiguous duplicate attributes fail closed.

`physics:body0` and `physics:body1` remain source relationships; they are not relabelled as universal parent/child links.

The parser does not claim layer composition, reference/payload resolution, variant evaluation, complete schema fallback processing or equivalence to the OpenUSD SDK.

A project-owned MIT fixture is maintained under `tests/fixtures/usd/`.

### Profile inspection

The historical `check` command mostly checked whether paths existed and concluded with “I am ready” language. The historical `boot` command tolerated failed modules and assembled an ad-hoc prompt without validating source integrity.

Both now use one fail-closed inspector.

`rgd check` validates:

- matching source-tree root;
- canonical kernel location;
- kernel identity and module list;
- safe and unique relative JSONC references;
- selected-module presence;
- selected modules parsing as JSON objects without non-finite values.

Its JSON output is:

```text
OPENRGD_PROFILE_VALIDATION
physical_execution_assessed = false
runtime_readiness = NOT_ASSESSED
```

`rgd boot` produces:

```text
OPENRGD_NON_ACTUATING_GROUNDING_CONTEXT
```

and always records:

```text
physical_execution.assessed = false
physical_execution.authorized = false
physical_execution.status = NOT_AUTHORIZED_BY_BOOT
```

It does not initialize an embodied runtime, assess the Operation Safety Gate or claim that a robot is ready.

## Merge gates

Before merge, reviewers should explicitly decide:

1. whether `OpenRGD/openrgd` is accepted as the non-actuating canonical root;
2. whether independent standard/toolchain/contract version axes are accepted;
3. whether `OPENRGD_SOURCE_TREE_SHA256_V1` is accepted as the integrity profile;
4. whether generated products remain untracked under the adopted authority model;
5. whether Agent Contracts remain candidate material or enter formal promotion;
6. whether the missing AION-ready archive is recovered or explicitly excluded;
7. how `main` protection and required checks are configured.

## Release gates

A public release additionally requires:

- release/version scope and migration notes;
- commit and artifact signing policy;
- a decision on whether full OpenUSD support is in or outside the release contract;
- a clear external-runtime and Body Adapter dependency statement;
- no claim of generic seed/body or physical safety certification.
