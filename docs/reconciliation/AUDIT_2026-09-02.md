## Closure 1 — specification, mirror and seed

`spec/` is the human-readable normative source. `standard/` is a strict-JSON mirror. The packaged default seed is a derived profile.

## Closure 2 — runtime and safety boundary

The historical bundled ROS 2 / Viam runtime was incomplete and referenced a nonexistent `02_operation/safety_supervisor.jsonc`. It was not repaired by guessing.

Resolution:

- preserve original runtime/adaptor/template blobs under `docs/history/runtime-prototype/`;
- remove the active bundled runtime from the installed package;
- retain `rgd run` only as a non-actuating status/migration namespace;
- block legacy `ros2`, `viam` and `hybrid` runtime commands with exit code `2`;
- assign physical execution to an independent embodied runtime and Body Adapter.

No existing safety file was renamed or reinterpreted as the missing module.

## Closure 4 — URDF evidence and static ROS 2 lifecycle

### Owned fixture

The branch admits one project-owned, MIT-licensed, hermetic fixture:

```text
tests/fixtures/urdf/openrgd_minimal_arm.urdf
tests/fixtures/urdf/PROVENANCE.md
```

It is synthetic, non-normative and non-actuating. It contains revolute, prismatic and fixed joints, with no external meshes, package references, local addresses or machine-specific paths.

### URDF importer

The reconciled importer emits only:

```text
spec/01_foundation/description.jsonc
spec/01_foundation/actuation_dynamics.jsonc
```

It records source filename, format, byte count and SHA-256. It does not persist an absolute machine path.

It extracts source-supported:

- links and inertial properties;
- parent/child joint topology;
- origins and axes when present;
- revolute/prismatic limits with correct unit-specific field names;
- mimic and source dynamics when present.

It does not synthesize:

- kernel identity or loading policy;
- alignment or ethical policy;
- safety limits absent from the source;
- cognition/capabilities;
- HAL drivers, bus addresses or hardware authorization.

Missing values remain missing. Malformed and non-finite numeric values fail closed.

### Seed enrichment

`rgd alive` remains an explicit enrichment operation. It personalizes the seed kernel DID and bundle identifier, overlays exact-path imported evidence and recalculates the canonical source root.

The project manifest records:

```text
profile_kind = SEED_ENRICHED_IMPORTED_EVIDENCE
seed_profile = <selected seed>
seed_compatibility_status = UNVERIFIED
```

A matching hash proves which files are present. It does not prove that inherited seed calibration, HAL, safety or behavioural assumptions are correct for the imported body.

### Static ROS 2 export

`rgd export ros2` is now a deterministic, non-actuating static exporter. It requires:

1. a matching canonical source root;
2. a deterministic machine bundle generated from that same root.

Every successful export writes:

```text
ros2_control.yaml
rgd_limits.xacro
export_manifest.json
```

`rgd_hardware.xacro` is emitted only if every exported joint has explicit HAL interfaces and the complete set resolves to one system driver plugin.

Otherwise the export remains:

```text
CONFIGURATION_ONLY
```

and records missing bindings. No generic driver, fake CAN identifier or convenient physical default is inserted.

For imported partial bodies, inherited seed actuator/HAL mappings are ignored. A matching joint name is not accepted as provenance for a driver.

## Merge gates

Before merge, reviewers should explicitly decide:

1. whether `OpenRGD/openrgd` is accepted as the non-actuating canonical root;
2. whether independent standard/toolchain/contract version axes are accepted;
3. whether `OPENRGD_SOURCE_TREE_SHA256_V1` is accepted as the source/profile integrity contract;
4. whether generated products and local robot workspaces remain untracked;
5. whether Agent Contracts remain candidate material or enter a formal promotion process;
6. whether the missing AION-ready snapshot is recovered or explicitly excluded;
7. whether `seed_compatibility_status = UNVERIFIED` is accepted as the honest current boundary;
8. how branch protection and required checks are configured.

## Release gates

A public release additionally requires:

- USD importer evidence/provenance hardening or explicit exclusion;
- modernization or careful scoping of `check` and `boot` claims;
- signing policy for commits, release artifacts and attestations;
- release notes distinguishing standard, toolchain and contract maturity;
- an explicit statement that static ROS 2 export is not physical execution certification.
