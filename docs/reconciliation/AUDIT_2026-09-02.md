## Resolved findings

### O-001 — Packaged seed drift

**Previous severity:** HIGH  
**Status:** RESOLVED ON BRANCH  
**Classification:** IMPLEMENTATION DIVERGENCE → VERIFIED DERIVED PROFILE

The initial audit found 10 missing JSONC files and 3 byte-divergent files. The differences were classified from direct evidence:

- `01_foundation/actuation_topology.jsonc`: seed revision `1.1.0` was superseded by normative revision `1.4.0`;
- `01_foundation/surface_properties.jsonc`: seed revision `1.0.0` was superseded by normative revision `1.2.0`;
- `00_core/kernel.jsonc`: no evidence supported a semantic runtime override; the seed header drift was replaced with canonical bytes;
- the missing extension policy, installed-skill registry, skills library, skill index, four core skills and two schemas were restored from `spec/`;
- the separate strict-JSON two-entry skill index was archived under `docs/history/seed/`;
- stale generated unified JSON/JSONC products were removed from the active seed.

## Open findings

### O-002 — Runtime references a missing safety module

**Severity:** HIGH  
**Status:** OPEN  
**Classification:** IMPLEMENTED PROTOTYPE WITH BROKEN REFERENCE

`src/openrgd/runtime/core/engine.py` loads:

```text
02_operation/safety_supervisor.jsonc
```

No file with that name exists in the current `spec/02_operation/` domain. The domain instead contains artifacts such as `runtime_validation.jsonc` and `safety_critical.jsonc`.

**Required decision:** map the engine to an approved, typed safety contract or isolate/remove the prototype runtime from release packaging. This audit does not guess which file is semantically equivalent.

## Merge gates

Before this branch can be considered merge-ready, reviewers should explicitly decide:

1. whether candidate contracts belong in the canonical root under their current maturity label;
2. whether the proposed repository authority and independent version axes are accepted;
3. whether the prototype runtime is fixed, excluded or separately versioned;
4. how bundle integrity hashes are generated;
5. how generated aggregates and robot-instance copies are governed;
6. whether the unavailable `openrgd-v0.2-aion-ready` artifact is recovered or explicitly excluded;
7. how `main` protection and required checks are configured.

The previous seed-drift gate is closed by executable evidence and is no longer a merge blocker.

## Release gates

A public release additionally requires:

1. scoped tag/version policy;
2. deterministic aggregate-bundle generation and verification;
3. complete CLI lifecycle tests;
4. resolution of the unavailable `openrgd-v0.2-aion-ready` evidence or an explicit exclusion statement;
5. artifact and commit signing policy;
6. release notes that distinguish standard, toolchain and contract maturity;
7. resolution or formal exclusion of the prototype runtime defects.

## Non-actions

This reconciliation pass intentionally did **not**:

- modify or force-update `main`;
- create a tag or GitHub release;
- populate empty placeholder repositories;
- declare HyperKernel a normative dependency;
- merge RGD-Physics, Chronograf, embodied runtime, LeRobot or Ethics implementations into this repository;
- silently authorize seed overrides;
- regenerate or delete aggregate bundles whose equivalence is not yet proved;
- expose or require private chain-of-thought.
