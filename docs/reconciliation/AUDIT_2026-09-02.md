## Open findings

### O-001 — Packaged seed drift

**Severity:** HIGH  
**Status:** OPEN  
**Classification:** IMPLEMENTATION DIVERGENCE

The repository validator reports:

```text
10 JSONC files missing from the packaged default seed
0 extra JSONC files in the packaged default seed
3 byte-divergent JSONC files
```

Divergent files:

```text
00_core/kernel.jsonc
01_foundation/actuation_topology.jsonc
01_foundation/surface_properties.jsonc
```

Missing examples include extension-permission metadata, installed-skill metadata and core skill definitions. The kernel difference may include intentional seed/profile wording, so this audit does not synchronize it blindly.

**Required decision:** define which differences are templating/profile differences and which are stale copies; then make CI fail on unintended drift.

### O-002 — Runtime references a missing safety module

**Severity:** HIGH  
**Status:** OPEN  
**Classification:** IMPLEMENTED PROTOTYPE WITH BROKEN REFERENCE

`src/openrgd/runtime/core/engine.py` loads:

```text
02_operation/safety_supervisor.jsonc
```

No file with that name exists in the current `spec/02_operation/` domain. The domain instead contains artifacts such as `runtime_validation.jsonc` and `safety_critical.jsonc`.

**Required decision:** map the engine to an approved contract or isolate/remove the prototype runtime from release packaging. The audit does not guess which file is semantically equivalent.

### O-003 — Placeholder integrity hash

**Severity:** MEDIUM  
**Status:** OPEN  
**Classification:** SPECIFIED BUT NOT MATERIALIZED

The bundle manifest still contains:

```text
sha256:placeholder_auto_generated
```

**Required decision:** define canonical serialization and hash scope before replacing the placeholder. Writing an arbitrary digest would create false integrity.

### O-004 — Multiple derived specification copies

**Severity:** MEDIUM  
**Status:** OPEN  
**Classification:** LEGACY / DERIVED COPY AMBIGUITY

The repository still contains `spec/`, `standard/`, packaged seeds, unified specifications, `RGD-ur5/` and `my-robots/RGD-ur5/`. The branch defines their intended authority but has not yet proven complete reproducibility between all copies.

**Required action:** build a deterministic generation/check pipeline and then remove or archive redundant copies only after equivalence is demonstrated.

### O-005 — Missing `openrgd-v0.2-aion-ready` source archive

**Severity:** MEDIUM  
**Status:** OPEN / NOT FOUND IN AVAILABLE WORKSPACE  
**Classification:** EVIDENCE GAP

The reconciliation notes refer to a later `openrgd-v0.2-aion-ready` artifact, but the archive itself was not available during this pass. No content from that unavailable archive has been invented or imported.

### O-006 — Limited behavioral tests

**Severity:** MEDIUM  
**Status:** OPEN  
**Classification:** TEST COVERAGE GAP

The current suite verifies repository invariants, contract validation and causal ordering, while the CLI smoke test covers help/registration. It does not yet exercise full `init → check → compile → export → boot` behavior against temporary fixtures.

### O-007 — Candidate contracts are not accepted standard

**Severity:** GOVERNANCE  
**Status:** OPEN  
**Classification:** PROPOSED / CONVERGENCE CANDIDATE

The imported cognition, somatic, Chronon-memory and Ethos/DecisionTrace contracts are reviewable and validated structurally, but remain explicitly marked **CONVERGENCE CANDIDATE**. Merge of this branch must not be interpreted as automatic promotion to stable normative status unless that decision is made explicitly.

### O-008 — Commit and artifact signing

**Severity:** LOW FOR DRAFT, HIGHER FOR RELEASE  
**Status:** OPEN  
**Classification:** RELEASE HARDENING

The current branch commits are not cryptographically verified by GitHub, and the Windows artifact is digest-addressed but not signed. This does not block draft review; it should be addressed before a trust-sensitive public release.

## Merge gates

Before this branch can be considered merge-ready, reviewers should explicitly decide:

1. whether candidate contracts belong in the canonical root under their current maturity label;
2. how to reconcile the 10 missing and 3 divergent seed files;
3. whether the prototype runtime is fixed, excluded or separately versioned;
4. how bundle integrity hashes are generated;
5. whether the proposed repository authority and independent version axes are accepted.

## Release gates

A public release additionally requires:

1. scoped tag/version policy;
2. deterministic specification and seed generation;
3. full CLI lifecycle tests;
4. resolution of missing `openrgd-v0.2-aion-ready` evidence or an explicit statement that it is excluded;
5. artifact/signing policy;
6. release notes that distinguish standard, toolchain and contract maturity.

## Non-actions

This reconciliation pass intentionally did **not**:

- modify or force-update `main`;
- create a tag or GitHub release;
- populate empty placeholder repositories;
- declare HyperKernel a normative dependency;
- merge RGD-Physics, Chronograf, embodied runtime, LeRobot or Ethics implementations into this repository;
- silently overwrite divergent specification copies;
- expose or require private chain-of-thought.
