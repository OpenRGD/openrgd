## Secret and debris controls

`.gitignore` now excludes:

- `.env` and environment variants, while allowing clean `.env.example`/`.env.template` files;
- private-key and certificate-key formats;
- credential/service-account JSON filenames;
- Python bytecode and package metadata;
- virtual environments and test caches;
- generated bundles, robot workspaces and interoperability exports.

`tools/validate_hygiene.py` scans every tracked text file and fails CI on:

- secret-bearing filenames;
- common API-token/private-key patterns;
- non-placeholder assignments to known secret variables;
- generated bytecode/build/package artifacts;
- machine-local absolute paths outside historical/spec evidence;
- reintroduced stale/prototype surfaces;
- unverified operational contact/domain assertions outside the registered draft-spec scope;
- new unregistered draft-spec contact or institutional assertion literals.

The secret-assignment parser is line-bounded and regression-tested so an empty template variable cannot absorb a value from the following line.

## AION maturity decision

The recovered AION work contains real executable evidence:

- Aion512/T-512 64-byte roundtrip;
- HyperAion 2080-byte roundtrip;
- a limited semantic-map loader;
- explicit vector-threshold violation extraction;
- a limited source-structure validator;
- six passing snapshot tests.

It does not prove a production microkernel, real-time scheduler, zero-copy IPC, process isolation, Chronograf bridge, hardware bridge or full semantic-first constitutional resolver.

Ten concrete hardening findings are registered in the AION backup audit, including non-finite vector acceptance, lossy integer coercion, incomplete semantic-map validation, fail-open mapping errors, unsupported runtime claims and conflict with the converged somatic/body boundary.

The AION material remains outside PR #1 and requires a separate post-merge evidence-delta pull request.
